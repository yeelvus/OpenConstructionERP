### 综合看板数据模型（`data_latest.json`）

```text
{
  meta: { title, month, generated, fx_cny_to_thb, unit, sources, counts },
  projects: [ { code, name, bucket, contract, resp_cost, actual, forecast, ... } ]
}
```

每个项目大致四层指标：

1. **商务/投标**：contract、resp_cost（责任成本）、bid_margin、settle、progress  
2. **预算人材机**：budget_labor/mat/mach/mgmt、分材料量价（钢筋/砼/砂浆…）  
3. **过程发生**：proc_*（人工构成、采购、商混、机具）、sub_*（分包合同/已付）、fin_*（付款科目/月序列）  
4. **对比与风险**：cmp_rebar / cmp_concrete、alerts、margin_erosion、cost_progress_gap  

金额单位：**万泰铢**（看板 meta），汇率 `fx_cny_to_thb` 用于人民币预算换算。

### 人工费 HTML 数据模型

- 内嵌 JS：`months[]` + `allData[project_key] = { zh_formal, zh_labor, local_*, agency, visa, ... }` 月度数组  
- 按**项目**分页/目录 + 累计趋势 + 构成趋势  
- 项目键未必是 `THCC-`（部分无编码），与 OCE `project_code` 需映射表  

### 上游数据域（生成信息.txt）

| 域 | 本地路径体系 | 与 OCE 已有能力 |
|----|--------------|----------------|
| 报公司成本表 | 月度 xlsx | 无直接对应 |
| 预算人材机 std | `3_预算部分/2_人材机_std` | BOQ / costmodel 预算线可对接 |
| 人工 | `Z_report/人工费汇总.xlsx` | 无专门模块 |
| 采购+商混 | `9_采购台账` + 搅拌站报表 | procurement / costs 部分可对接 |
| 机具 | `10_机具费` sum | equipment 部分可对接 |
| 分包 | `5.1_分包合同` sum | **contracts（分包）** 已可部分对齐 |
| 财务付款 | `12-财务数据` sum/std | **finance 付款导入** 已在做 |
| 责任成本 std | `3.1_责任成本` | 可映射到 costmodel / 自定义责任成本表 |

## 2. 与 OCE 现有模块的关系（不要重复造轮子）

| OCE 模块 | 路径/能力 | 与看板关系 | 建议 |
|----------|-----------|------------|------|
| **projects** | 项目主数据、`project_code` | 看板 `code` ↔ THCC 编码 | **必须**作为关联主键 |
| **finance** | 发票/付款/预算线 | `fin_*` 已可部分来自付款导入 | 看板读 finance 聚合，**不**再维护第二套付款真相 |
| **contracts** | 总包/分包金额 | `sub_*`、合同额 | 读 contracts 台账汇总 |
| **costmodel (5D)** | EVM、S 曲线、预算 spine | 过程成本/预测接近，但粒度是 5D 不是 THCC 人材机台账 | 并列：5D=工程维度；看板=经营台账维度 |
| **boq** | 清单金额 | 投标/预算参考 | 可选对照 |
| **analytics / reporting / bi-dashboards** | 通用 KPI/报表 | 通用能力强，但缺 THCC 字段语义 | **不**把 80+ 字段硬塞进 BI 配置，易碎 |
| **costs / cost-explorer** | 成本库 | 采购单价分析可复用 | 二期 |

**结论：** 综合成本看板是 **跨域经营看板（portfolio cost cockpit）**，不是单一 finance 子页，也不是 5D 的替换。适合做成 **独立 OCE 模块**，数据层对接 projects + finance + contracts +（导入的）THCC 快照。

## 3. 推荐模块形态（按 OCE 惯例）

### 3.1 模块命名与位置

| 层 | 建议 |
|----|------|
| 模块 id | `oe_thcc_cost_board`（或 `oe_cn_cost_analytics`） |
| 后端 | `backend/app/modules/thcc_cost_board/` |
| 前端 | `frontend/src/features/thcc-cost-board/` |
| 路由 | `/cost-board`（组合层）、`/projects/:id/cost-board`（项目层） |
| 侧栏 | 放在 **`grp_cost_control` 或 `grp_finance`**：如「综合成本看板」 |
| 权限 | `thcc_cost_board.read` / `.import` / `.admin` |

标准文件集（与 finance / costmodel 一致）：

```text
manifest.py
permissions.py
models.py          # 快照 + 可选明细表
schemas.py
repository.py
service.py
router.py
# 可选 seed.py / importer/
```

### 3.2 信息架构（页面）

```text
/cost-board                         # 组合层（对标 index.html）
  ├─ 月度选择 + FX + 数据新鲜度
  ├─ KPI 卡片（在建/完工/风险/毛利）
  ├─ 图表（毛利率、人材机预算 vs 过程…）
  └─ 项目表（筛选 bucket/code）→ 点行进项目层

/projects/:projectId/cost-board     # 项目层（对标弹窗 6 Tab）
  ├─ 总览（责任成本 / 已发生 / 预估 / 毛利）
  ├─ 预算人材机
  ├─ 采购材料
  ├─ 预算 vs 采购（量价）
  ├─ 分包 · 责任成本
  └─ 财务付款

/cost-board/labor                   # 人工费专题（对标人工费 HTML）
  ├─ 项目目录
  └─ 单项目：累计趋势 + 构成趋势（中方/属地/中介/签证）

/cost-board/import                  # 数据更新（对标 build_unified_cost_dashboard.py）
  ├─ 扫描 Z_report / 各域 sum 路径（Docker 挂载 /host/thcc）
  └─ 生成/导入当月 snapshot
```

### 3.3 数据架构（核心）

**不要**把 400KB HTML 当运行时依赖；以 **JSON 快照 + 可重建流水线** 为准。

#### 表设计（建议最小集）

1. **`oe_thcc_cost_snapshot`**  
   - `id`, `period`（如 `2026-06`）, `fx_cny_to_thb`, `unit`, `generated_at`, `source_meta`（json）, `status`

2. **`oe_thcc_cost_project_row`**  
   - `snapshot_id`, `project_id`（可空 FK）, `project_code`, `name`, `bucket`, `payload`（jsonb：其余 80+ 字段）  
   - 常用筛选列可冗余：`contract`, `resp_cost`, `actual`, `progress`, `exp_margin` 便于列表排序

3. **`oe_thcc_labor_series`**（人工专题）  
   - `period_month`, `project_code`, `category`（zh_formal/zh_temp/local/agency/visa…）, `amount`, `currency`

4. 可选后续：采购明细、机具明细拆表（一期可先放在 `payload` 内）

#### 与 OCE 实时数据的关系

| 字段组 | 一期 | 二期目标 |
|--------|------|----------|
| `fin_*` | 快照 JSON | 由 finance 付款表按项目/科目聚合覆盖或对照 |
| `sub_*` | 快照 | contracts 分包 total_value / 付款 |
| `contract` | 快照 / 项目 contract_value | 合同台账总包合计（你们已区分台账 vs 项目合同额） |
| `budget_*` | 快照 | 责任成本/人材机 std 导入后写库 |
| `proc_*` / 采购 | 快照 | 采购台账导入模块 |

**原则：** 快照保证「每月经营会」可复现；实时源逐步替代 payload 内对应字段，并在 UI 标注「快照 / 实时」。

## 4. 实施路径（分阶段，风险可控）

### 阶段 0 — 嵌入式只读（1–2 天，验证需求）

- Docker 挂载 `Z_report`（已有 `/host/thcc`）  
- 新路由「综合成本看板」：  
  - **A)** iframe / 静态托管 `index.html` + `data_latest.json`（最快）  
  - **B)** 或仅托管 `data_latest.json`，用 React + recharts 重画组合层  
- 人工费页：iframe 现有 HTML 或读内嵌 JSON 后用 React 重画  
- **不写业务表**；证明导航、权限、项目跳转  

**优点：** 立刻可用。  
**缺点：** 与 OCE 主题/权限/项目上下文弱绑定；难做中英双语与移动端。

### 阶段 1 — 模块化快照（推荐主路径，约 1–2 周）

1. 后端 `thcc_cost_board`：导入 `data_latest.json` → snapshot 表  
2. 导入 `人工费汇总.xlsx` 或解析劳动 HTML 的 `allData` → labor_series  
3. 前端 React 复刻组合层 + 项目 6 Tab + 人工专题（对齐现有视觉优先级）  
4. 项目表行 → `/projects/:id/cost-board`（`project_code` 匹配）  
5. 侧栏入口 + `ModuleGuide`  

### 阶段 2 — 与 OCE 数据打通

- 财务 Tab：优先 finance 付款（你们已有 THCC 付款导入）  
- 分包 Tab：contracts  
- 预算/责任成本：std 导入器（可复用 excel_io 模式）  
- 刷新策略：按钮「从挂载目录重建快照」≈ 现 `build_unified_cost_dashboard.py` 迁入 `service.rebuild_snapshot()`

### 阶段 3 — 专题扩展

- 采购分析 HTML/Excel（钢筋、桩）  
- 商混搅拌站  
- 与 5D costmodel 对照（进度–成本缺口）  
- 导出 PDF/Excel（对齐 reporting）

## 5. 技术选型建议

| 项 | 建议 | 理由 |
|----|------|------|
| 前端图表 | **recharts**（OCE 已有） | 避免再引 Chart.js CDN；与主题一致 |
| 表格 | ag-grid 或现有 Table | 项目一览筛选/排序 |
| 金额 | `MoneyDisplay` + 明确单位「万 THB」 | 避免与 BOQ 本币混淆 |
| 静态 HTML | 仅阶段 0 过渡 | 长期维护成本高 |
| 构建脚本 | Python 迁入 backend importer | Docker 内可读 `/host/thcc` |
| Docker | 继续 bind-mount 邯郸中材 | 与付款导入同一挂载策略 |

## 6. 模块边界（做什么 / 不做什么）

### 做

- 经营会级 **组合 KPI + 项目钻取**  
- 月度快照版本与归档（替代 archive/ 目录）  
- 人工费时间序列专题  
- 与 `project_code` 的深链  

### 不做（或后做）

- 替代 5D EVM / S 曲线（保留 costmodel）  
- 替代 finance 做凭证级账务  
- 在 BI 模块里用通用 widget 拼 80 字段（难维护）  
- 把原始 HTML 当唯一真相源

## 7. 与现有定制的协同

| 已有定制 | 协同方式 |
|----------|----------|
| 项目 `project_code` / 去重 | 看板 `code` 关联主键 |
| 合同台账金额 vs 项目合同额 | 看板合同额优先台账总包；对照 contract_value |
| 财务付款 std 导入 | 项目层「财务付款」Tab 读 live + 快照对照 |
| Docker `/host/thcc` | 快照重建与付款导入共用挂载 |
| BOQ 清单金额 | 总览可增加「清单 vs 责任成本」对照条 |

## 8. 风险与注意点

1. **单位**：看板为 **万泰铢**；OCE 付款/合同可能是元/THB 绝对值 → UI 必须标注，导入时统一换算规则。  
2. **无编码项目**：`code` 为空时用名称归一化匹配（与 dedupe 的 name key 一致）。  
3. **双份 HTML 语义重叠**：综合看板 vs 项目成本统计报告 → 只保留一个「官方」组合入口，另一份作归档导入。  
4. **脚本依赖本地路径**：生成脚本在 `Desktop/code`，迁入 OCE 后路径改为配置/挂载。  
5. **前端体积**：人工 HTML 内嵌大数据；入库后按项目懒加载 series。  
6. **权限**：经营数据敏感 → 默认 manager+ / 自定义角色。
